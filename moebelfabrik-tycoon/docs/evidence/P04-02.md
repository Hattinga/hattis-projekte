## Verifiziert

| Fall | Tatsächliches Ergebnis |
| --- | --- |
| Eigene Holzcharge aufnehmen | Erfolgreiche Prüfung `OK`; Bestands-JSON vor/nach jedem Fall identisch. |
| Profil nicht freigegeben | `NOT_READY`, auch bei fehlendem Kontext. |
| Fremder Eigentümer/unerlaubter Akteur | `NOT_AUTHORIZED`; Kontext kommt aus getrenntem Serverargument. |
| Im Request gefälschter Actor | Geschlossener Request verwirft das zusätzliche Feld mit `INVALID_REQUEST`. |
| Mengen 0, −1, 2, Bruch, NaN, Unendlich und Text | Jeweils `INVALID_QUANTITY`; nur die vollständige Charge mit Menge 1 ist zulässig. |
| Veraltete oder ungültige Revision | `STALE_REVISION` beziehungsweise `INVALID_REQUEST`; keine Umbuchung. |
| Fehlende Charge, geänderte Quelle, unbekanntes Ziel | Unterscheidbare Fehlercodes mit deutscher Rückmeldung. |
| Gleicher Ort, anderer Träger, direkter Transport ohne Hand | `SAME_LOCATION`, `WRONG_CARRIER`, `CARRIER_STEP_REQUIRED`. |
| Ziel belegt oder falsche Stufe | `TARGET_FULL` beziehungsweise `WRONG_STAGE`; Bestand unverändert. |
| Mitarbeiter und Band | Mitarbeiter nutzt eigenen Träger; Band nimmt Bausatz am Sägeausgang auf und prüft Ablage am Montageeingang über denselben Vertrag. |
| Zwischenprodukt auf Anhänger | Abgewiesen, selbst wenn künstliche Standort-Metadaten diese Stufe erlauben würden. |
| Ungültiger Gesamtbestand | `INVALID_STATE`, keine wirtschaftliche Aktion. |
| Sichtbarkeit | Servermodule auf dem Client nicht vorhanden. |

Der [Datenvertrag](../technical/STATE.md#implementierte-aktionsprüfung-p04-02) beschreibt Argumente und Verantwortungsgrenzen. ## Grenzen und nächster Schritt

Der Code validiert, führt aber noch keine Übergabe aus. Er beweist keine räumliche Erreichbarkeit, echte Bandverbindung, Maschinenfreigabe oder aktive Spielsitzung. Diese Fakten muss ein späterer Serverhandler selbst ermitteln und mit den nachfolgenden Zustands-/Persistenzdiensten verbinden. Es gibt noch keine wirtschaftlich aktive Handaktion oder Spieleroberfläche.
